## 1. About DeepGene v1

DeepGene v1 is a local-first, research-oriented bioinformatics framework for
organising, analysing, and communicating evidence about SCN1A variants.

The system combines:

- a source-preserving SCN1A ClinVar evidence pipeline;
- a normalized SQLite evidence database;
- quality-control and descriptive analysis reports;
- transparent evidence profiles and feature policies;
- research-only functional-effect modelling;
- AlphaMissense annotation ingestion;
- a local browser dashboard;
- Research Chat with optional external AI assistance; and
- a Data Lab for validated dataset uploads.

DeepGene v1 is a research foundation. It is not a diagnostic system,
pathogenicity classifier, disease-risk calculator, treatment recommender, or
replacement for geneticist review.

> **Research-only boundary:** All model outputs are exploratory results for
> analysis and hypothesis generation. They must not be used as clinical advice
> or as a patient-level medical decision.

## Live deployment and local-first workflow

The current public browser deployment is available at the
[DeepGene research copilot](https://deepgene-sand.vercel.app/). It provides a
shareable hosted interface for the Research Chat experience and the Data Lab
entry point.

The hosted app and the local dashboard serve different purposes:

| Environment | Best use | Data and execution model |
|---|---|---|
| [Live Vercel app](https://deepgene-sand.vercel.app/) | Sharing the interface and demonstrating the research workflow | Hosted browser experience; do not use it for private or sensitive data |
| Local dashboard | Full development, analysis, validation, uploads, and controlled experiments | Local-first execution with the project database, processed data, models, and audit outputs |

The live deployment is a research demonstration, not a replacement for the
local research workspace. Deployment configuration, hosted storage, API
availability, and resource limits may differ from the local environment.
For reproducible analysis, private datasets, model development, retraining,
and debugging, use the local dashboard described below.

Both environments preserve the same research-only boundary: outputs are
exploratory and must not be interpreted as diagnoses, pathogenicity
classifications, disease-risk estimates, treatment recommendations, or
replacements for geneticist review.

## 2. What we built in version 1

The completed v1 workflow is:

~~~text
Source-preserved research data
            ↓
Validation and normalization
            ↓
SQLite evidence database and processed tables
            ↓
Evidence, phenotype, representation, and ML audits
            ↓
Transparent baselines and leakage checks
            ↓
Research-only functional candidates
            ↓
Local dashboard, Research Chat, and Data Lab
~~~

The design keeps four concepts separate:

| Concept | Meaning in DeepGene |
|---|---|
| Evidence | Submitted observations and classifications, such as ClinVar records |
| Annotation | Supporting computational information, such as AlphaMissense scores |
| Label | An explicit target, such as an experimentally reported LOF or GOF effect |
| Prediction | An output generated by a trained research model |

This separation prevents an existing clinical classification or annotation score
from silently becoming an independent training label.

## 3. Version-one dataset and evidence layer

### 3.1 SCN1A ClinVar evidence

The primary evidence layer was built from source-preserved SCN1A ClinVar
data:

~~~text
data/raw/SCN1A_clinvar.tsv
data/raw/variant_summary.txt.gz
data/processed/SCN1A_clinvar_clean.csv
data/database/scn1a.db
~~~

Current database snapshot:

| Entity | Count |
|---|---:|
| Genes | 1 |
| Unique SCN1A variants | 5,381 |
| Variant representations | 10,696 |
| ClinVar evidence records | 10,696 |

The database separates biological identity, genomic representation, and submitted
evidence:

~~~text
genes
  └── variants
        ├── variant_representations
        └── clinvar_records
~~~

The ClinVar layer preserves clinical significance, review status, submitter
context, phenotype descriptions, HGVS names, assemblies, genomic coordinates,
and dbSNP identifiers.

### 3.2 Evidence and quality-control results

The v1 analysis pipeline includes:

- variant and representation statistics;
- clinical-significance distributions;
- review status and submitter analysis;
- conflict and evidence-quality analysis;
- phenotype availability and parsing;
- assembly, coordinate, allele, HGVS, and dbSNP checks;
- evidence consistency audits;
- feature redundancy and scale audits;
- leakage and target-independence audits;
- model uncertainty and error analysis; and
- target-permutation sanity testing.

Important current findings:

- coordinate coverage is 10,686 of 10,696 representations, or 99.91%;
- all current representations have complete reference and alternate alleles;
- all current representations have dbSNP identifiers;
- 5,315 representations are available in both GRCh37 and GRCh38;
- 3,413 record-level entries are uncertain significance;
- 772 record-level entries contain conflicting classifications;
- 22 unique variants have expert-panel review;
- phenotype information is present for all current parsed variants and records.

These statistics describe the current database snapshot. They do not represent
the complete biological space of SCN1A variation.

### 3.3 Phenotype and evidence representation

The project preserves phenotype descriptions and produces normalized and
profile-level outputs:

~~~text
data/processed/deepgene_phenotype_normalized_v1.csv
data/processed/deepgene_phenotype_profiles_v1.csv
data/processed/deepgene_variant_profiles_v1.csv
~~~

The current v1 parser preserves source phenotype descriptions and availability.
Full ontology normalization, patient-level cohort representation, and validated
phenotype prediction are future work.

## 4. Functional datasets and machine learning

### 4.1 Independent functional-effect analysis

The original independent functional-effect branch was kept separate from
ClinVar pathogenicity evidence.

The primary supervised table contains:

| Property | Value |
|---|---:|
| Variants | 51 |
| Columns | 26 |
| Functional classes | 3 |
| Loss class | 35 |
| Mixed class | 12 |
| Gain class | 4 |
| Biological predictors | 14 |

The predictors are protein position and amino-acid physicochemical properties:

- hydrophobicity;
- charge;
- molecular volume;
- absolute and signed changes; and
- same-amino-acid status.

Identifiers, phenotype, inheritance, ClinVar evidence variables, and the target
itself were excluded from the predictors.

The majority-class balanced-accuracy baseline was 0.3333. Repeated
cross-validation produced:

| Model | Balanced accuracy |
|---|---:|
| Logistic Regression | 0.2750 ± 0.0740 |
| Random Forest | 0.3032 ± 0.1663 |

The target-permutation audit did not show unusually high performance compared
with randomized labels. Therefore, no final predictive model was selected from
this branch. This is an exploratory negative or insufficient predictive finding,
not evidence that the biological features have no relationship with functional
effect.

### 4.2 Generation-2 cross-channel candidate

The Generation-2 source is represented by:

~~~text
data/raw/scion_clean_tbl.csv
data/raw/generation2_source_manifest.json
data/processed/deepgene_gen2_scion_harmonized_v1.csv
data/processed/deepgene_gen2_ml_ready_v1.csv
data/model/deepgene_generation2_gbm.pkl
~~~

The source contains 375 functional records across nine sodium-channel genes.
Forty exact overlaps with the earlier functional set were excluded, leaving
335 rows for the current matrix.

The candidate uses engineered amino-acid features and gene indicators. Its
primary validation is leave-one-gene-out evaluation.

~~~text
Gradient Boosting balanced accuracy:
0.6368 ± 0.1465
~~~

Comparison models were also evaluated:

| Model | Mean balanced accuracy |
|---|---:|
| Logistic Regression | 0.6144 |
| Random Forest | 0.6196 |
| SVM with RBF kernel | 0.5938 |
| Gradient Boosting | 0.6368 |

This is a source-dependent research benchmark, not clinical validation or fully
independent external validation.

Source: [SCION](https://github.com/christianbosselmann/SCION).

### 4.3 SCN1A experimental supplementary candidate

The project also uses public SCN1A functional supplementary data:

~~~text
data/raw/SCN1A_Brunklaus_2020_supplementary.xlsx
data/processed/deepgene_scn1a_brunklaus_2020_functional.csv
data/model/deepgene_scn1a_supplement_candidate.pkl
data/analysis_results/49_scn1a_supplement_model.json
~~~

The source contains 59 rows. The preparation workflow retains 40 explicit
binary labels:

~~~text
LOF: 36
GOF: 4
~~~

Mixed, unclear, insufficient-data, no-effect, and missing-label rows are
excluded rather than forced into a binary class.

The candidate combines these labels with the harmonized functional table,
deduplicates variants, and trains a Gradient Boosting classifier.

| Metric | Result |
|---|---:|
| Combined deduplicated rows | 377 |
| Internal holdout rows | 95 |
| Balanced accuracy | 0.718 |
| ROC-AUC | 0.750 |

The holdout is an internal random split, not an independent external test set.
The artifact is research-only and is not a pathogenicity or diagnostic model.

Source: [UCL Discovery](https://discovery.ucl.ac.uk/id/eprint/10091164/).

### 4.4 Dravet branch

The Dravet clinical-outcome branch is intentionally blocked until a separate,
reviewed clinical label file is available.

LOF/GOF labels cannot be substituted for Dravet labels because SCN1A functional
effects span multiple clinical phenotypes.

Required future fields are:

~~~text
variant_key
dravet_label
label_source
source_accession
cohort_id
reviewer_status
~~~

Unknown and unresolved cases must remain unknown rather than becoming negative
labels.

## 5. AlphaMissense annotation ingestion

The Data Lab accepts:

~~~text
data/uploads/AlphaMissense_gene_hg38.tsv.gz
data/processed/alphamissense_gene_hg38.csv
~~~

The expected fields are:

~~~text
transcript_id,mean_am_pathogenicity
~~~

The current uploaded table contains 19,233 rows. The ingestion pipeline:

1. accepts the gzip-compressed file;
2. skips comment lines;
3. detects the required columns;
4. validates score values in the interval [0, 1];
5. writes a normalized CSV; and
6. records the upload in the audit log.

AlphaMissense is stored as annotation evidence. It does not trigger LOF/GOF
retraining because it is not a reviewed experimental label set.

## 6. How the DeepGene software was built

### 6.1 Repository structure

~~~text
Project_DeepGene_2.0/
├── app/                    Local server and browser frontend
├── data/raw/               Source-preserved datasets and manifests
├── data/processed/         Normalized and feature-ready tables
├── data/database/          SQLite database and database scripts
├── data/data_analysis/     Evidence, phenotype, and QC analyses
├── data/ml/                Reproducible ML preparation and training scripts
├── data/model/             Research model artifacts and metadata
├── data/ml_results/        ML feature, split, and evaluation outputs
├── data/analysis_results/  JSON and text analysis reports
├── data/uploads/           Data Lab uploads and upload audit
├── data/memory/            Local conversation memory, ignored by Git
├── docs/                   Version-one research manuscript
├── CONTRIBUTORS.md         Project acknowledgements
├── LICENSE                 Project license
└── README.md               Project documentation
~~~

### 6.2 Evidence pipeline

~~~text
ClinVar source data
       ↓
SCN1A extraction and cleaning
       ↓
SQLite database
       ↓
Statistics and evidence audits
       ↓
Evidence profiles and transparent baseline
       ↓
Research-only modelling and dashboard access
~~~

The processing scripts are numbered so that major transformations can be
reproduced and inspected. Raw source files are retained whenever practical,
and named reports document the output of each analysis stage.

### 6.3 Leakage control

An existing ClinVar classification must not be used as a feature when that same
classification is being evaluated. Otherwise, the model can reproduce an answer
already present in its input without demonstrating independent predictive ability.

DeepGene therefore separates:

~~~text
Evidence used for prioritization ≠ Labels used for evaluation or training
~~~

The feature-policy and leakage-audit outputs document which identifiers,
phenotype fields, clinical classifications, and functional targets are excluded
from each modelling task.

## 7. Local dashboard, Research Chat, and Data Lab

The local dashboard is the complete DeepGene development and analysis
environment. It remains the canonical workflow for source-preserving data,
the SQLite evidence database, model artifacts, validated uploads, audit logs,
and reproducible experiments.

Start the dashboard from the project root:

~~~powershell
python app/server.py
~~~

Open <http://127.0.0.1:8765/>.

The frontend contains two main pages:

### Research Chat

Research Chat supports:

- local database questions;
- project and dataset explanations;
- model-status questions;
- learning-loop explanations;
- optional external AI conversation;
- local conversation continuity; and
- workspace metrics and safety messaging.

### Data Lab

Data Lab supports:

- validated ClinVar CSV/TSV ingestion;
- validated functional-data processing;
- controlled research-candidate retraining; and
- AlphaMissense .tsv.gz annotation ingestion.

### Optional external AI provider

The current implementation uses OpenRouter:

~~~powershell
$env:OPENROUTER_API_KEY="your-real-key"
python app/server.py
~~~

Without a key, the local evidence assistant remains available. If the external
provider fails, the server falls back to local answers.

The API key is read from the server environment and should never be committed
to the repository.

### Conversation memory

Chat turns are stored locally in:

~~~text
data/memory/conversations.jsonl
~~~

This is retrieval-style context. It does not update the weights of an external
AI model and does not turn ordinary conversation into validated ML labels.
The memory file is ignored by Git because it may contain sensitive research
notes.

## 8. Data Lab upload behaviour

| Input | v1 behaviour |
|---|---|
| ClinVar CSV or TSV | Validate and import into the evidence workflow |
| Functional CSV or TSV | Validate and prepare a research candidate |
| AlphaMissense .tsv.gz | Decompress, validate, and store as annotation |

The upload endpoint is POST /api/upload. Accepted uploads are recorded in:

~~~text
data/uploads/upload_audit.jsonl
~~~

No upload is automatically promoted to a clinical model.

## 11. Limitations and responsible use

1. ClinVar contains submitted assertions with heterogeneous evidence, review
   status, and possible conflicts.
2. Record counts and unique-variant counts are not interchangeable measures of
   independent biological observations.
3. Functional effects are assay- and context-dependent; LOF, GOF, mixed, and
   normal effects are not interchangeable clinical outcomes.
4. The available functional datasets are small and source-dependent.
5. The primary 51-variant analysis did not justify selecting a final model.
6. The SCN1A supplementary metric comes from an internal holdout.
7. AlphaMissense scores are annotations, not ground-truth clinical labels.
8. Phenotype strings are not yet a complete patient-level phenotype model.
9. Conversation text is not automatically trustworthy training data.
10. No current DeepGene artifact is a diagnostic, pathogenicity, disease-risk,
    treatment, or clinical decision model.

Third-party datasets retain their own licenses and usage conditions. Review the
original source terms before redistribution or clinical use.

## 12. Future version updates

The following items are planned for future versions and are not completed v1
capabilities.

### Version 2 research direction

DeepGene v2 will investigate evidence-aware and uncertainty-calibrated
prioritization of SCN1A variants. The planned workflow is:

~~~text
SCN1A variant
      ↓
Evidence extraction and normalization
      ↓
Evidence integration
      ↓
Uncertainty estimation and calibration
      ↓
Explainability and evidence completeness
      ↓
Research prioritization
      ↓
Expert review support
~~~

Planned v2 work includes:

- freezing v1 as a reproducible baseline;
- creating a formal SCN1A master table and data dictionary;
- adding population-frequency evidence;
- expanding computational, structural, conservation, splice, and functional
  evidence;
- normalizing phenotype terms with validated ontology mappings;
- using unique-variant and cohort-aware dataset splits;
- comparing transparent baseline models with evidence-aware models;
- evaluating calibration, uncertainty, and missing-evidence behaviour;
- adding explainable evidence-group contributions;
- conducting VUS prioritization as a separate experiment;
- adding independent expert-reviewed benchmarks;
- performing temporal, ablation, and external validation; and
- preparing reproducible figures, tables, and a version-two manuscript.

Future work must preserve the v1 principles:

- evidence, annotations, labels, and predictions remain separate;
- missing and conflicting evidence remains visible;
- ambiguous labels are not forced into binary classes;
- conversation is not treated as automatic ground truth;
- model performance is not presented as clinical validity without appropriate
  validation; and
- clinical deployment is not claimed unless independent evidence genuinely
  supports it.

**DeepGene v1 is a reproducible research foundation, not a completed clinical
  product.**
